# Explicit folders for new conversations

Setup: Run the app against an authenticated external Codex server. Keep an existing project, a pinned thread, and a legacy Documents/Codex dated chat with a direct thread URL. Record the legacy directory and session contents before testing.

1. Open Home without a cwd query or folder selection. Submit a prompt. Expect a message asking for an existing workspace, no thread/start RPC, and no new directory or session. Repeat with the worktree runtime selected.
2. Select an existing folder and submit. Expect a conversation in that folder; send another message and refresh to confirm history and selection persist. Select an existing worktree directory; expect it to be used directly without creation.
3. Inspect the sidebar and its organize menu in project and chronological modes. Expect Projects and Pinned, with no Chats section, Chats first option, dedicated chat creation, or chat expansion controls. Conversations in dated directories such as `~/Documents/Codex/2026-11-12/hello` appear under `hello`, like any other project.
4. Navigate project and pinned threads, then open the saved legacy direct URL. Expect existing history and normal continuation. Compare legacy session and directory contents; no automatic deletion or migration should occur.
5. Register an unrelated empty workspace while the dated directory is unregistered. Expect both the empty project and `hello` to remain visible. Register `hello`; expect one project and one row per conversation. Remove its workspace registration; expect its returned conversations to remain visible. Refresh, then wait for background history pages; expect the same visibility and no duplicate rows.
6. Search for a dated-directory conversation by title and content in both layouts. Expect normal matching rows. Open it and expect `hello` to be the active project; open the new-conversation folder picker and expect its existing directory as an option. Pin it; expect one row in Pinned and no duplicate in project/global rows. Archive or delete a disposable conversation; expect it to disappear normally.
7. With server history containing a missing or blank working directory, expect those conversations under the stable `Conversations` group in both layouts, including with unrelated registered roots. Do not offer a blank directory for new-conversation creation.
8. Repeat sidebar navigation at desktop, 375x812, and 768x1024 in light and dark themes. Expect usable navigation and consistent surfaces.

Cleanup: Remove only conversations or worktrees explicitly created for this test using normal user controls. Preserve legacy data.

Performance audit: a synthetic run through the actual workspace-union and both sidebar visibility helpers with 10,000 threads across 200 discovered projects plus 100 empty registered roots took 132.90 ms cold and 96.91–109.28 ms over five warm runs. All 300 projects and 10,000 chronological rows were retained. The existing duplicate-leaf collection still compares threads against registered roots (O(threads × roots)); sidebar filtering is linear before the existing sorting. Discovery adds no requests, filesystem scans, per-thread reads, payload fields, or cache invalidation. Existing page merging deduplicates thread IDs and reapplies grouping after each page and root update. Full DOM rendering, browser timing, and live authenticated server behavior were not measured by this audit.
